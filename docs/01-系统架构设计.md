# 《智能实验室数字孪生运营驾驶舱》系统架构设计

## 1. 系统定位

不是普通 BI 报表，而是实验室「运营中心 + 设备资源调度中心 + 实验效率分析中心 + AI 辅助决策中心」四位一体的大屏决策系统。系统默认进入驾驶舱首页，无登录模块。

## 2. 技术架构总览

```
┌──────────────────────────────── 前端 (Vue3 + TS + Vite) ────────────────────────────────┐
│  大屏布局 / 玻璃拟态设计系统 / Pinia 状态                                                 │
│  Three.js 数字孪生   │  ECharts 数据分析  │  AntV G6 关系分析  │  WebSocket 实时刷新     │
└──────────────┬──────────────────────────────┬──────────────────────────────┬───────────┘
               │ HTTP/REST (JSON)             │ WebSocket (/ws)              │
┌──────────────▼──────────────────────────────▼──────────────────────────────▼───────────┐
│                              后端 (Spring Boot 3 + MyBatis Plus)                        │
│  控制层 Controller ─► 服务层 Service ─► Mapper(MyBatis Plus)                             │
│  统一响应/全局异常/CORS  │  Redis 缓存热点统计  │  WebSocket 推送服务  │  AI 统计引擎      │
└──────────────┬──────────────────────────────┬───────────────────────────────────────────┘
               │ SQL                          │ 同步任务
┌──────────────▼─────────────────────────────▼───────────────────────────────────────────┐
│  MySQL (业务 OLTP，23 表)          ClickHouse (分析 OLAP，事实/维度表，亿级聚合)          │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- **前端**：Vue3 + TypeScript + Vite；可视化 Three.js（数字孪生）、ECharts（数据分析）、AntV G6（关系分析）；WebSocket 实时刷新。
- **后端**：Spring Boot 3（JDK17）、MyBatis Plus（ORM）、Redis（热点缓存）、WebSocket（STOMP 广播）、内置统计算法（AI 模块，无外部依赖）。
- **数据库**：MySQL（业务 OLTP）+ ClickHouse（历史大数据 OLAP，支持亿级查询）。

## 3. 模块划分（对应需求 15 章）

| 模块 | 定位 | 关键能力 |
|---|---|---|
| 一、首页驾驶舱 | 门面 | 六大指标卡 + 实时更新时间 |
| 二、数字孪生 | 空间感知 | Three.js 3D 设备 + 状态颜色 + 点击详情 + WS 实时 |
| 三~十一、分析看板 | 数据洞察 | 设备利用率/事业部/机种/申请/完成率/异常/结果/DQA/报价 |
| 十二、AI 预测 | 决策辅助 | 资源预测/延期风险/瓶颈/效率/部门排行/资源推荐 |
| 十三、关系分析 | 关系洞察 | G6 部门→项目→设备→结果网络 |
| 十四、ClickHouse | 大数据底座 | 事实/维度表 + 增量同步 + 聚合查询 |
| 十五、代码工程 | 企业级交付 | 分层架构 + 文档 + 部署说明 |

## 4. 分层与数据流

- **数据流**：MySQL 业务表 → (统计 SQL / 服务层聚合) → REST API → ECharts 看板；MySQL 变更 → 广播 → WebSocket → 前端实时刷新（大屏指标卡 + Three.js 模型颜色）。
- **异步链路**：MySQL → 增量同步任务 → ClickHouse 事实表 → 历史趋势/亿级聚合接口 → 分析看板（日/周/月长周期趋势优先走 ClickHouse）。
- **接口规范**：统一响应体 `{code, message, data}`；`/api/dashboard/**`、`/api/analysis/**`、`/api/ai/**`、`/api/relation/**`；WebSocket 端点 `/ws`，频道 `device-status`、`experiment-status`。

## 5. 每模块「设计原因 / 解决的企业问题 / 业务价值」

- **首页驾驶舱**：一屏汇总运营 KPI，解决"管理层看不到全局、多系统割裂"的问题；价值：秒级掌握实验室当日运转，缩短决策响应。
- **Three.js 数字孪生**：把设备状态从表格抽象为空间模型，解决"设备在哪、谁在占用、何时释放"不可见的问题；价值：直观定位瓶颈设备与空置资源，提升机台周转率。
- **设备利用率/事业部/机种分析**：量化资源占用与分布，解决"资源分配拍脑袋、跨部门抢占无依据"的问题；价值：为设备扩容/排产/跨事业部调度提供数据依据。
- **实验申请/完成率分析**：透视申请量与交付进度，解决"申请积压、完成情况不透明"的问题；价值：识别申请高峰与交付短板，支撑产能规划。
- **异常(NG)分析**：多维度归因 NG（项目/机种/设备/人员/原因），解决"质量问题只知结果不知根因"的问题；价值：聚焦高频失效点，驱动良率提升。
- **结果/DQA 分析**：只统计已有判定结果（不判定），解决"合格率口径分散、DQA 专项无法沉淀"的问题；价值：统一质量基线，量化 DQA 各评价维度的表现。
- **报价分析**：汇聚收入与成本分布，解决"实验收费与设备收入无排行、成本趋势不明"的问题；价值：支撑定价与资源配置的商业决策。
- **AI 预测**：内置统计/回归算法（设备压力预测、延期风险、瓶颈、效率、部门排行、资源推荐），解决"靠经验排产、事后补救"的问题；价值：事前预警满载与延期，推荐最优设备与周期，把决策从被动转为主动。
- **G6 关系分析**：以图网络呈现部门/事业部/设备/项目/机种/人员关系，解决"要素孤立、关联不可视"的问题；价值：一键追踪任意节点的影响链路。
- **ClickHouse**：OLTP 库不适合亿级历史聚合，ClickHouse 列式+分区承接历史趋势；价值：日/周/月/季度长周期分析保持秒级响应。

## 6. 关键设计决策

1. **无登录**：默认直达驾驶舱首页，路由不设鉴权拦截。
2. **MyBatis Plus 只读为主**：驾驶舱以读多写少，写路径（送检/计划/负荷）由既有业务系统维护，本系统聚焦读取与聚合，避免与业务写库冲突。
3. **Redis 缓存**：热点统计（首页指标、排行）短 TTL 缓存，降低高频大屏刷新对 MySQL 的压力。
4. **WebSocket 推模型**：服务端在数据变更后主动广播，前端订阅频道更新，替代轮询，保证大屏实时性。
5. **ClickHouse 为可选加速层**：分析接口按数据源路由（短周期走 MySQL，长周期/亿级走 ClickHouse），未部署 ClickHouse 时自动回退 MySQL。
6. **AI 内置算法**：时序回归（设备压力）、规则+评分（延期风险/瓶颈）、统计（效率/排行）、协同过滤式推荐（资源推荐），无外部 LLM 依赖。
